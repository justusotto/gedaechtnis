# What runs when

Eleven hook events, in twenty matcher entries carrying thirty-four hook commands (`hooks/hooks.json`):

| when | what it does |
|---|---|
| Before a Bash command | In the vault: refuses `git add -A`, a bare `commit`, `--amend`, backticks inside a double-quoted `-m`, a push to anything but a `backup` remote, and `reset --hard` / `clean -f`. Asks before `rm` against the vault or the Trash (and, in the vault, caches, databases and mined media). With `require_launch_model: true`, requires every `claude` launch to pin `--model` and `--effort`. With `"suite_gate": true`, holds a `git merge` or `git push` until a full test run on the commit being shipped — or one with the identical tree — is recorded green; the run records itself through the repository's root `conftest.py`, and the gate never runs tests. `SUITE_GATE_ALLOW=1` at the start of the command lets one through. |
| Before an Edit or Write | Holds a session to the vault paths its `.atlas-lane` marker declares. Ships in `warn` mode, which logs what it would have refused; write `deny` into `partition.mode` in the state directory to enforce it. Refuses a whole-file `Write` over an existing note and offers Edit instead, so another session's lines are not silently replaced. Takes a per-file lock until the tool returns; a lock older than ten seconds is stale and is taken over. Refuses a new file named after a display name (`Decisions.md`) and gives the stem to use (`Canon.md`). |
| Before a subagent call | In the vault or a marked project: refuses a sub-agent starting its OWN sub-agent unless its brief says `fanout: allowed`, and refuses more than `agent_max_concurrent` live sub-agents in one session. With `require_agent_model: true`, requires a `model` unless the agent's definition names one. Before a message to another live session on this machine, the resume gate refuses one that would wake an idle session too large or too cold to wake cheaply, and parks it for that session; a session that compacted after its last measured call passes as "compacted, not yet measured". A message of at most `resume_short_chars` (1,500) characters to a warm session under `resume_window` is delivered; a longer one is delivered while it fits under that window and is parked otherwise. |
| Before a Read | Says if this file is byte-identical to one already read this session, or if a whole-file read is over `big_read_kb`. Never refuses, and never answers your permission prompt for you. |
| After an Edit or Write | Adds a queue file's missing trailing newline. Flags commit SHAs that resolve in no known repo. Lists files still citing a heading an edit just removed. Adds a newly written role file's row to that project's `Map.md`. Records the vault path written, which is what the Stop commit is built from. Appends a row to a folder's `Inbox.md` when the writer came from elsewhere. |
| After a Bash command | Releases the per-file locks a shell write took. |
| After a published artifact | Records its title and id in the vault's artifact index and commits that one file. |
| After any tool | Says once per level and context window that this session has passed the reach line, the warn line or the cap; a compaction opens a new window. Never blocks, never acts. Loads a facet — a `Kernel-<name>.md` rule file beside a folder's boot file — the first time this call matches the tools, command patterns or paths its frontmatter lists — from the session's own folders, or from anywhere when the facet says `scope: always`; once per session, logged to `facets.log`. |
| At session start | Prints lane, writable paths, partition mode, vault HEAD, uncommitted count, unread inbox and ledger rows. On a fresh start in the vault or a marked repo it also injects the operating rules. Lists the facets of this session's folder and what loads each. Takes this session's per-region writer claim; each later prompt takes it if it is not yet held (and repeats the claim line only when it changed), and loads a facet the prompt names with `facet:<name>` or through a queue row it cites. With a `session_name_pattern` set, lists the managed sessions that are still running and marks the ones that have stopped moving. |
| At session start and at every prompt | Shows this session the messages the resume gate parked for it, newest first, at most 6,000 characters at a time, each framed as a peer's report and not the owner's word; a message older than 48 hours is listed, not shown. Shown lines move to `parked-<name>.delivered.jsonl`. An error shows nothing and leaves the messages unread. |
| When a message from another session arrives | If it says it merged a commit (`MERGED <sha>`, ``merged `<sha>` ``), checks that commit against `main` with git — in this repository, else in the vault — and adds the one-line answer to the session's context. Never blocks. `python3 hooks/mergesha.py verify-merge <sha> [<repo>]` asks the same question by hand. |
| At Stop | Gives back exactly the claims this session took. Commits this session's own vault writes, path-limited, as a fixed machine identity: never `git add -A`, never `--amend`, never another session's half-written file. Then works out whether a cleanup or a synthesis pass is due, and whether anything the next session boots with has stopped being true. It can also move the oldest entries of an over-long memory file or Boot file into an archive file, remove finished worktrees under `.claude/worktrees/`, and move finished copy-on-write clones of the repo from the clones folder to `~/Downloads/To delete <date>/` (moved with a ledger; nothing is deleted); until you switch those on it only lists what it would do (see [Configuration](configuration.md)). If this session was launched with a `--name` the installation manages, and it either wrote a handoff or ran out of context, it leaves one message for the session that started it. At most once every five minutes across the machine, it also checks the live Claude sessions (those `tools/sessions.py launch` started and those it did not) and lists the finished ones: its last turn ended and is `session_close_idle_minutes` old (or the handoff it wrote says DONE, LANDED or STOPPED and no turn began after its commit, or it reported to its seat; either one and 30 minutes of quiet); no tool call, prompt, recent background task, scheduled wake-up or live process it started still open. Its last words are printed, not obeyed. What cannot be told for certain (git could not answer, uncommitted files it wrote, a conversation you typed into; an unreadable screen or an old background task when it could not be read that nothing of its own runs) keeps it only until its last turn is 4 × that age; the close then lists those files. `session_close_apply` is on as shipped (set it `false` to get the list only, each with the `claude -r <name>` line that reopens it). It closes a finished session only when it is one `tools/sessions.py launch` started (same pid AND start time as recorded) or one you started by hand whose record in the CLI's own session registry names its pid with a start time within 1 s of the live process (a `claude` started from a shell, never a Desktop session, never one you typed into after its first prompt), runs inside that launch's own `screen`/`tmux` session (a hand-started one: its own `screen` window) with only shells in between, is not a Remote Control host, not attended, and has no name on `session_close_never`; the close is quitting that `screen`/`tmux` session, never a signal to a process and never `kill -9`, and each close and refusal goes to `close.log`. `tools/sessions.py close --dry-run` prints what it would close and why. `tools/sessions.py close --when-needed` closes the oldest finished ones only while swap in use is at or above `session_close_swap_used_mb` (MB) or the memory-pressure level is below `session_close_memory_floor`, and stops once the machine is under that line. |
| Before a typed `/compact` | Only with `compact_point: "on"`: refuses while this session's newest compact point is missing, stale, unfilled or over 8,000 characters; `/compact force …` passes. A second hook on the same event is registered to wake the session with the refusal (`asyncRewake`), so that the session fixes its point and says READY itself; it judges a refusal again a second later and stays silent when the door let that `/compact` through. That this reaches the session has not been seen live yet, so if it does not answer within a minute, ask it to run `/compact-ready`. An automatic compaction never reaches either, and an error in them lets the compaction through. |
| After a compaction | With `compact_point: "on"`: puts the recorded compact point back into the session word for word (after an automatic compaction, headed by a line saying it was not checked this time), and logs whether the summary still names its file. |
| When a subagent stops | Gives back what it was holding, so its parent is not left waiting. |
| When a subagent starts | Records it as running, under its id, for the sub-agent cap. |
| On worktree create / remove | Makes a copy-on-write clone for an isolated build. On removal it fetches the clone's commits back into the source repo first, then deletes the clone only if it holds nothing unique. Uncommitted work goes to the Trash, never `rm`. |

Logs live under the state directory, one file per hook or door (`deny.log`, `partition.log`, `chore.log`, `session.log`, `hook-errors.log`, `facets.log`, `scope.log` and others).
